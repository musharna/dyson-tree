`web/fixtures.json` is generated by `tools/make_fixtures.py` (committed) and
carries `provenance.git_sha`, the md5 of each `sim/` module, the prereg md5,
and the interpreter/library versions. The k grids, solve window and `n_grid`
are read from `experiments/q1_crossover/prereg.yaml` — never retyped.

**Positive control on the generator.** The six crossover values it produced are
identical to the six in the committed `experiments/q1_crossover/crossover.csv`
(17.9688 / 12.7058 / 8.9844 / 88.3162 / 62.4490 / 44.1581). The fixture file
therefore agrees with the experiment's own committed output, not merely with
itself.

### Contents

- Display grid: `linspace(0.5, 100, 400)` AU — deliberately NOT the log-spaced
  bracketing grid the root-finder uses, so parity is not checked only at the
  points the solver is most accurate at.
- Per preset (`vascular`, `algal`): the preset's fields, `leaf_respiration`,
  `organism_respiration`, `irradiance(r)`, `equilibrium_temperature(r)`,
  `net_carbon_at_equilibrium(r)` on the grid.
- Per preset × per registered `k`: `net_carbon(r, k)` on the grid,
  `compensation_irradiance(org, k)`, and `crossover_distance_for(org, k,
  n_grid=200)` — `null` where there is no root.

### Edge cases (all inside the model's own domain)

| name | what it pins |
| --- | --- |
| `no_crossover_in_window` | algal at `k=5`: the root lies beyond `r_max`, so `crossover_distance_for` RAISES. JS must report `null`, not extrapolate. Python message recorded. |
| `compensation_at_respiration_boundary` | `r_d == a_max == 10.0` with `t_set == t_ref`: leaf respiration equals `a_max` exactly, so there is no compensation point. Python raises; JS must too. |
| `algal_t_min_floor` | `T_eq` crosses the algal floor (254.65 K, Pointing et al. 2015) at **1.194466 AU** — the same 1.1945 AU floor Q2b reports as binding. Sampled at `0.999·r`, `r`, `1.001·r`: the response is 0 **at** the floor (Python uses `t <= t_min`), so a port written with `<` fails here. |

### Declared tolerances

`abs_err <= atol + rtol * |ref|`, declared in the fixture file itself:

| quantity | rtol | atol | reason |
| --- | --- | --- | --- |
| irradiance, gross, respiration, T_eq, compensation | 1e-9 | 0 | closed form |
| `temperature_response` | 1e-9 | 1e-15 | exact 0 below `t_min`, where a relative bound has no meaning |
| `net_carbon`, `net_carbon_at_equilibrium` | 1e-9 | 1e-12 | a difference that passes through zero at the crossover; near the root `\|ref\|` is ~1e-17 and a pure relative bound would demand bit-exact cancellation of two O(1) terms. 1e-12 µmol is ~1e-13 of the grid-end values. |
| `crossover_au` | 1e-6 | 1e-6 AU | bracketed root: JS bisects where Python uses `brentq(xtol=1e-6)`, so agreement is bounded by solver tolerance, not float precision |

No tolerance has been loosened. If one ever is, the reason is written beside it
in `web/fixtures.json` and the number is never changed silently.

**Stage 1 DONE:** fixtures exist, are generated by a committed script, carry the
SHA, and reproduce the committed experiment output.

## Stage 2 — JS port and parity

`web/model.js` ports `sim/physiology.py`, all of `sim/thermal.py`, and the parts
of `sim/organism.py` the page displays (`Organism` as a frozen plain object,
`leafRespiration`, `organismRespiration`, `netCarbon`,
`netCarbonAtEquilibrium`, `compensationIrradiance`, `crossoverDistanceFor`).
Every function names the `sim/` lines it came from; presets are copied verbatim.
`Organism.net_carbon_adapted` is deliberately NOT ported — it is Q2b's runner
path, nothing on the page shows it, and an unused port is an untested surface.

The root-finder is not `brentq`: `crossoverDistance` brackets on the first sign
change of the same log-spaced grid, then bisects to 1e-12 AU — tighter than the
declared 1e-6 AU tolerance, so the tolerance describes `brentq`'s `xtol` rather
than this solver's.

`web/package.json` (`{"type": "module"}`) exists only so `node` reads `web/*.js`
as ES modules. No build step, no dependency, no CDN.

**Fixtures extended in this stage.** `tools/make_fixtures.py` now also emits
`adapted_t_opt_home_1au`, `temperature_response` and
`temperature_response_gaussian` per preset, because `thermal.py` is ported whole
and a ported function with no fixture is a check that cannot fail. Regenerated:
all six crossovers unchanged (17.9688 / 12.7058 / 8.9844 / 88.3162 / 62.4490 /
44.1581).

### Where the verdict lives

`web/parity.mjs` recomputes every fixture quantity and prints raw numbers only —
it makes no pass/fail judgement. `tests/test_parity_js.py` owns every
comparison, so the implementation under test never reports its own verdict. If
`node` is missing the test FAILS rather than skips.

```
$ python -m pytest -q
131 passed in 4.76s          # 122 pre-existing + 9 parity
```

### Positive controls inside the parity suite

- `test_fixture_provenance_matches_this_tree` — md5s of `sim/physiology.py`,
  `sim/thermal.py`, `sim/organism.py` and the prereg must match what the fixture
  recorded, so stale fixtures fail loudly instead of passing against an old model.
- `test_js_crossovers_match_the_committed_experiment` — the JS crossovers are
  compared against `experiments/q1_crossover/crossover.csv` itself. Without it,
  `model.js` and `fixtures.json` could agree perfectly with each other while both
  disagreeing with the number the repository published.

Six of nine tests fail and the first failure names the mutated quantity by name.

**Mutant 2: a false claim of my own, caught by running it.** The floor test
originally asserted that `t <= t_min` vs `t < t_min` in `temperatureResponse`
was what it discriminated. Mutating `<=` to `<` **passed 9/9** — at `t == t_min`
the ramp evaluates to `(t - t_min)/(t_opt - t_min) = 0` under either spelling,
so the two are behaviourally identical and that rationale was untestable. The
comment in `tools/make_fixtures.py`, the `why` string in the fixture, and the
assertion message were all corrected to say what the case actually pins, and a
mutant it genuinely catches was substituted: **deleting the floor clamp**.

```
$ sed -i '/if (t <= tMin) return 0.0;/d' web/model.js
$ python -m pytest tests/test_parity_js.py -q
E   AssertionError: temperature_response [t_min floor outside]: |-0.00292481806...
FAILED tests/test_parity_js.py::test_js_edge_case_t_min_floor
2 failed, 7 passed
```

Below the floor an unclamped ramp returns a **negative** response — which would
make the gross term of net carbon negative — and the test names that sample.
Restored; 131 pass.
